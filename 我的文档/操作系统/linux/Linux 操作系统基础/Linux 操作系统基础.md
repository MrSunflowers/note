# 磁盘与分区

在进行操作系统安装之前首先需要对磁盘进行分区，无论是任何操作系统，这一步骤都是必须的。

磁盘分区表是硬盘上用于管理分区信息的核心数据结构，**它独立于操作系统而存在**，用于定义硬盘空间如何被划分为不同的逻辑部分。通常存储在硬盘的第一个物理扇区，这个扇区被称为 ​​主引导记录（Master Boot Record, MBR）​​ 或（对于 UEFI/GPT 分区）​​GUID 分区表头（GUID Partition Table Header）​​。

目前主流的两种分区表形式为 MBR（主引导记录）和 GPT（全局唯一标识分区表），它们在容量支持、分区数量、安全性等方面存在显著差异。

一、MBR 分区表（Master Boot Record）

MBR 是传统的分区方案，自 1983 年沿用至今，其核心特点如下：

1. 容量限制：最大支持 2TB（Terabytes） 硬盘容量。若硬盘超过2TB，MBR无法识别超出部分，导致剩余空间浪费。
2. 分区数量：最多支持 4 个主分区。若需更多分区，需将其中一个主分区转为扩展分区，并在其内创建逻辑分区（逻辑分区数量理论上无上限，但受操作系统限制）。
3. 数据安全性：分区表存储在硬盘第一个扇区（512字节），无冗余备份。若该扇区损坏（如病毒攻击），可能导致全部分区信息丢失。
4. 兼容性：兼容所有操作系统（包括 Windows XP 及更旧版本）和传统BIOS启动模式。

由于历史原因，现在的操作系统还是有一大部分使用 MBR 分区方式，其最大特点即存在逻辑分区特性

在最初设计 MBR 分区方式时，其最多仅支持 4 个分区。后续随着科技发展，4 个分区的上限已不够使用，此时即引入了扩展分区的概念，即将原本 4 个分区中的一个作为扩展分区，在扩展分区中再进行分区拆分，以达到突破分区上限的目的，这也导致了在 Linux 系统中，主分区以 1,2,3,4 来表示，拓展分区中的逻辑分区以 5 为最小分区编号。

二、GPT 分区表（GUID Partition Table）

GPT是现代分区方案，针对大容量硬盘设计，主要优势包括：

1. 容量支持：理论最大支持 9.4ZB（Zettabytes）（1ZB=1024EB，1EB=1024PB，1PB=1024TB），实际可满足未来数十年存储需求。
2. 分区数量：理论上分区数无上限，但 Windows 系统限制为128个主分区，无需扩展分区即可直接管理。
3. 数据安全性：分区表在磁盘开头（LBA 1）和结尾各存一份，并支持CRC32校验。若主分区表损坏，可自动从备份恢复。
4. 启动方式：需搭配UEFI固件启动操作系统（如Windows 8+/Linux新内核），传统 BIOS 无法引导 GPT 系统盘。

# 文件系统

磁盘的格式化实际上并不是为了清除磁盘上的数据，而是规定数据的存储方式，即初始化文件系统，这本质上是定义了数据将如何在该分区内被组织、存储、管理和访问。常见的文件系统有如FAT16、FAT32、NTFS、EXT2、EXT3、EXT4等。

当前 Linux 主流的默认文件系统主要是 EXT3 和 EXT4，EXT3 是 EXT2 的升级版（2001年发布），曾为早期 Linux 发行版（如 Ubuntu 10.04 前、CentOS 5）的默认文件系统，EXT4​​（第四代扩展文件系统）是绝大多数主流 Linux 发行版的默认选择。

EXT4 文件系统分为 Inode 存储区和数据块存储区，其中 ​​Inode 区为数据索引存储区，主要存储数据块的索引信息，即数据块在磁盘的位置信息，表现为一个 Inode 编号。在磁盘格式化时，其 ​​Inode 区的容量就会确定，且无法拓展，所以即使在磁盘空间未满时也可能因 Inode 耗尽而无法创建新文件，生产上曾存在因此产生的生产事故。一个实际的案例就是攻击者通过在磁盘中快速创建大量空文件，快速消耗 Inode 容量，导致磁盘无法存储。这种攻击在文件系统与邮件系统中尤为常见。

数据块存储区存储文件的实际内容，数据块的大小是固定的，在创建 EXT4 文件系统时可以通过 -b 选项设定（通常为 1KB, 2KB, 4KB）

假设数据块大小被规定为 4KB ，现在有一个 6KB 的文件，其占用的数据块实际上是 2 块，2 块数据块的总大小为 8KB，而文件仅占用 6 KB，值得注意的是，当文件未完全使用数据块的空间时，剩余空间也无法分配给其他文件使用，即**数据块是磁盘存储的最小单位**。

# 硬件设备

在 Linux 中，一切皆文件，包括硬件设备，在 Linux 中硬件设备也使用文件的形式来表示。

设备文件被存储在 `/dev` 目录下，其中

| **硬件类型**      | **设备文件名**            | **命名规则说明**                        |
| :---------------- | :------------------------ | :-------------------------------------- |
| IDE硬盘           | `/dev/hd[a-d]`            | `a`: 主盘, `b`: 从盘                    |
| SATA/SCSI/USB硬盘 | `/dev/sd[a-p]`            | 按检测顺序分配（sda, sdb, ...）         |
| 光驱              | `/dev/cdrom`或 `/dev/sr0` | 通常为/dev/sr0的符号链接                |
| 软盘              | `/dev/fd[0-1]`            | fd0: 第一软驱                           |
| 25针打印机        | `/dev/1p[0-2]`            | 并口打印机(LPT端口)                     |
| USB打印机         | `/dev/usb/1p[0-15]`       | USB接口打印机设备                       |
| 鼠标              | `/dev/mouse`              | 通常指向具体设备（如/dev/input/mouse0） |

例如 

`/dev/hda1` 表示第一块硬盘的第一个主分区
`/dev/hdb5` 表示第二块硬盘的第一个逻辑分区

## 挂载

在 Linux 中，磁盘分区必须挂载以后才能使用，当一个已挂载的分区无法正常使用时，Linux 可能表现为无法开机。

正常来说，Linux 的分区需要手动进行挂载，也可在安装时选择自动挂载，下面通过手动挂载的方式来说明必须进行单独挂载的目录。

- `/boot`(启动分区，推荐 1 GB)，启动分区一般应单独挂载，如何其他分区混用，当分区空间被写满时，表现为 linux 无法开机，无法清除垃圾文件。
- `/`(根分区)，Linux 要求根分区必须单独挂载，空间一般没有限制，一般控制在 20-50GB
- swap 分区(交换分区)，交换分区可类比于虚拟内存，当内存空间不足时，使用该空间代替内存使用，由于交换分区是内存分区，并不表现在文件系统中，没有独立的文件夹，Linux 推荐根据真实内存大小进行分配。如果真实内存小于4GB，交换分区推荐为真实内存的两倍；如果真实内存大于4GB，交换分区推荐与真实内存一致；
- `/home` (常用于文件服务器，不是必须单独挂载)
- `/www` (常用于Web服务器，不是必须单独挂载)

# linux 目录结构

以下是 Linux 标准目录结构的完整说明，符合 Filesystem Hierarchy Standard (FHS) 规范：

## Linux 核心目录结构及作用

| **目录**   | **英文全称**     | **核心功能**                         | **重要子目录/文件示例**                                      |
| :--------- | :--------------- | :----------------------------------- | :----------------------------------------------------------- |
| **/**      | Root             | 整个文件系统的根目录，所有路径的起点 | 不存放具体文件，仅包含系统目录                               |
| **/bin**   | Binary           | **基础系统命令**（所有用户可用）     | `cat`, `ls`, `cp`, `mv`, `bash`                              |
| **/sbin**  | System Binary    | **系统管理命令**（需 root 权限）     | `fdisk`, `ifconfig`, `iptables`, `reboot`                    |
| **/boot**  | Boot             | **系统启动文件**                     | `vmlinuz`(内核), `initramfs`, GRUB 引导文件                  |
| **/dev**   | Devices          | **硬件设备文件**                     | `sda`(硬盘), `tty`(终端), `null`(空设备)                     |
| **/etc**   | Etcetera         | **系统和应用配置文件**               | <ul><li>`fstab`：挂载配置</li><li>`passwd`：用户账户</li><li>`ssh/`：SSH配置</li><li>`apt/`：APT源配置</li></ul> |
| **/home**  | Home             | **普通用户家目录**                   | `/home/john`(用户私有文件/配置)                              |
| **/root**  | Root Home        | **管理员(root)家目录**               | 系统级配置文件/脚本                                          |
| **/lib**   | Libraries        | **系统库文件**（32位）               | `libc.so.*`(C库), 内核模块                                   |
| **/lib64** | 64-bit Libraries | **64位系统库文件**                   | 同上（64位架构专有）                                         |
| **/media** | Media            | **可移动设备自动挂载点**             | `/media/usb`(U盘), `/media/cdrom`                            |
| **/mnt**   | Mount            | **临时文件系统挂载点**               | 手动挂载目录如 `/mnt/nas`                                    |
| **/opt**   | Optional         | **第三方商业软件安装目录**           | `/opt/oracle`, `/opt/google`                                 |
| **/proc**  | Processes        | **内核/进程虚拟文件系统**            | <ul><li>`/proc/cpuinfo`</li><li>`/proc/meminfo`</li><li>`/proc/PID/`</li></ul> |
| **/run**   | Runtime          | **进程运行时数据**                   | `pid`文件, 套接字(sockets), 锁文件                           |
| **/tmp**   | Temporary        | **临时文件**（重启清空）             | 所有用户可写                                                 |
| **/usr**   | User             | **用户级程序与资源**                 | ️ 见下级分解                                                 |
| **/var**   | Variable         | **可变数据文件**                     | ️ 见下级分解                                                 |


## /usr 目录深度解析（二级目录）


| **目录**     | **功能说明**     | **典型内容**                                                 |
| :----------- | :--------------- | :----------------------------------------------------------- |
| /usr/bin     | 用户级应用程序   | `python`, `gcc`, `vim`                                       |
| /usr/sbin    | 系统管理补充命令 | `sshd`, `cron`                                               |
| /usr/lib     | 程序库文件       | 应用程序共享库                                               |
| /usr/include | 开发头文件       | C/C++头文件                                                  |
| /usr/share   | 架构无关数据     | <ul><li>文档：`/usr/share/man`</li><li>时区：`/usr/share/zoneinfo`</li></ul> |
| /usr/local   | 本地编译软件     | 源码安装的软件                                               |
| /usr/src     | 源代码           | 内核源码(`linux-headers-*`)                                  |

## /var 目录深度解析（核心子目录）

| **目录**   | **功能说明** | **典型内容**                            |
| :--------- | :----------- | :-------------------------------------- |
| /var/log   | **系统日志** | `syslog`, `auth.log`, `apt/history.log` |
| /var/cache | 应用程序缓存 | `apt/archives`(DEB包缓存)               |
| /var/lib   | 状态信息     | `mysql/`(数据库文件), `dpkg`(包状态)    |
| /var/spool | 队列数据     | `cron/`, `mail/`, `lpd/`(打印队列)      |
| /var/run   | 运行时信息   | `*.pid`(进程ID), 等效于`/run`           |
| /var/www   | Web内容      | Apache/Nginx默认网站目录                |
| /var/tmp   | 持久临时文件 | 重启后仍保留                            |

## 特殊目录说明

1. **/srv**

- 用途：存放服务数据（如Web/FTPServer的实际数据）

- 示例：`/srv/nginx`(网站数据), `/srv/git`(Git仓库)

2. **/sys**

- 特点：虚拟文件系统，暴露内核设备信息

- 作用：动态查看/修改设备参数

- 路径：`/sys/class/net/eth0`(网卡配置)

3. **/lost+found**

- 产生场景：文件系统修复(`fsck`)后

- 作用：存储恢复的碎片文件
